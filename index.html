range 切片是副本层序遍历写 for range queue 会把下一层混进来。这也是 Go 岗最容易暴露基本功的一处。
pivot 不能固定取中间快排用中间索引做 pivot，遇到有序数组会退化到 O(n²)。要能说出随机化或三数中。
nil 与空输入面试官第一眼就看有没有处理 nil / 空数组 / 单节点。
切片共享底层数组append 后再切片、以及把局部切片存进结果集，都可能互相覆盖。
map 并发写直接 panic这是 Go 的高频追问点，也是你做长连接推送时真正踩过的场景。

核心总结

为什么需要 P

  • Go 1.0 是 G-M 模型：一个全局 runq + 一把 sched.lock，核越多锁竞争越狠
  • M 之间无法迁移任务，一个 M 阻塞，它队列里的 G 全部饿死
  • Go 1.1 引入 P：把一把大锁拆成 N 把本地锁，P 数量 = GOMAXPROCS
  • 一句话定位：G 是任务，M 是执行资源（内核线程），P 是调度资源（持有 P 才能跑 G）

三层结构里最该记住的字段

  • G：stack（初始 2KB，可增长）、atomicstatus、sched（PC/SP 现场）
  • M：g0（调度专用栈，调度代码不占用户栈）、curg（当前 G）、spinning（自旋标记）
  • P：runq[256]（本地队列）、runnext（插队位）、mcache（内存分配无锁的关键）
  • runnext 的意义：handler 里 go process(req) 会插队，下个调度点立刻执行；被覆盖的那个才进 runq

调度循环：schedule → findRunnable → execute

  • 每 61 次调度才去全局队列捞一次（schedtick%61 == 0），避免每次抢 sched.lock
  • findRunnable 顺序：本地 runq → runnext → 全局队列 → netpoll(0) → stealWork → stopm 休眠
  • stealWork 最多尝试 4 次（stealTries），每次从受害者 P 偷一半（runqgrab 取 len/2）
  • 偷一半的原因：全偷会导致受害者立刻空队列、形成乒乓；一半是让双方都还有活干的最小化启发式
  • M 找不到活先自旋再休眠，因为线程唤醒是微秒级，比自旋贵

抢占：Go 1.14 的分水岭

  • 1.13 及以前只有协作式：函数序言检查 stackguard，死循环 for { i++ } 永远抢不到
  • 1.14 起改为信号式异步抢占：sysmon 发 SIGURG，signal handler 打标记，G 走到安全点才真正让出
  • 注意：抢占不是立即生效，只是打标记，要等安全点（函数序言 / 循环回边）
  • sysmon 阈值 forcePreemptNS = 10ms，意味着单个 G 最长可霸占 P 10ms

sysmon 看门狗

  • 独立后台线程，不需要 P；扫描间隔从 20µs 退避到 10ms
  • 职责：抢占运行超 10ms 的 P、回收 syscall 超时的 P（handoffp）、触发 netpoll、每 2 分钟强制 GC
  • syscall 时 P 被 handoff 给别的 M，原 M 裸跑系统调用，所以「一个慢 syscall 不会拖垮整个程序」

状态机与常见的混淆点

  • _Gidle → _Grunnable → _Grunning → _Gwaiting / _Gsyscall → _Gdead
  • _Gwaiting（等 channel/锁，M 已释放 P）与 _Gsyscall（在做系统调用，M 还占着）不是一回事
  • go f() 只入队不切换；阻塞是 gopark（被动让出），Gosched 是主动让出（生产代码基本不该出现）

现代版本细节（能说出来说明没背旧资料）

  • GOMAXPROCS 默认 = CPU 核数；Go 1.25 起容器感知（读 cgroup limit），K8s 里不用手动设
  • M 上限默认 10000（debug.SetMaxThreads）；P 数量固定，运行时改会触发 STW
  • mcache 挂在 P 上而不是 M 上，这是 P 存在的第二个理由（内存分配无锁）

高频追问 点开看答题要点

GOMAXPROCS 设多少合适？

默认核数即可；CPU 密集基本等于核数，IO 密集可略高但要压测验证。Go 1.25 起容器内自动感知 cgroup。

P 越多越好吗？

不是。P 多意味着 mcache/本地队列多、窃取成本上升、GC 需要扫描的 P 状态更多，且会加剧缓存不亲和。

为什么全局队列每 61 次才取？

全局队列要抢 sched.lock。每次都抢会把本地队列的收益吃掉。61 是经验质数，避免与 P 数量共振。

channel 阻塞后 G 去哪了？

gopark 把 G 置为 _Gwaiting，挂到 channel 的 sudog 队列；M 释放 P 去执行别的 G。

goroutine 泄漏怎么定位？

pprof/goroutine?debug=2 看堆积栈，常见原因是 channel 无人接收、无超时、WaitGroup 漏 Done。

1.14 的异步抢占是怎么实现的？

sysmon 发现 P 超 10ms 未让出，向该 M 发 SIGURG；handler 打标记，G 到安全点后走 gopreempt_m 让出。
