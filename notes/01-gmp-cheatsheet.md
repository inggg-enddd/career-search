# GMP 速记

> 一页纸版本，面试前扫一遍。完整版见「Go 深度」模块。

## 三个角色

| 角色 | 是什么 | 关键字段 |
|---|---|---|
| **G** | goroutine | 栈 2KB 起、atomicstatus |
| **M** | 内核线程 | g0（调度栈）、curg、spinning |
| **P** | 调度资源 | runq[256]、**runnext**、mcache |

## 一句话记住

- **M 必须持有 P 才能跑 G** —— P 是「许可」，M 是「劳动力」
- **runnext 只有 1 个位置** —— 所以「Go 调度是 LIFO」是错的
- **每 61 次调度才取全局队列** —— 因为要抢 `sched.lock`

## 查找顺序（背下来）

```
本地 runq → runnext → 全局队列 → netpoll(0) → 偷(4 次, 偷一半) → 休眠
```

## 调度时机

1. `go f()` —— 只入队，不切换
2. channel / mutex 阻塞 —— `gopark`，G 进等待队列，M 释放 P
3. syscall —— `handoffp`，P 交给别的 M
4. 抢占 —— sysmon 每 10ms 检查
5. GC 安全点

## 抢占演进

- 1.13-：协作式，只在**函数序言**检查 → 死循环抢不到
- 1.14+：`SIGURG` 异步抢占 → 死循环也能被打断

```go
// 这个循环在 1.13 之前会让整个程序卡死
for {
}
```

## 常见追问

- **P 越多越好吗？** 不是：mcache/本地队列变多、窃取成本上升、cache 不亲和
- **GOMAXPROCS 设多少？** 默认核数；1.25 起容器自动感知 cgroup
- **为什么线程唤醒比自旋贵？** 唤醒是微秒级系统调用，自旋是纳秒级
